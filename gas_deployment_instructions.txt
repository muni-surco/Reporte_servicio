# Instrucciones de Despliegue en Google Apps Script (GAS)

## 1. Archivos del backend
Copia el contenido de los siguientes archivos locales al editor de GAS
(uno por archivo, con el mismo nombre):

| Local | GAS |
|---|---|
| `Reporte_servicio/Code.gs` | archivo `Code.gs` (script principal) |
| `Reporte_servicio/Firebase.gs` | archivo `Firebase.gs` (conexión RTDB/Firestore) |
| `Reporte_servicio/QuadrantsData.gs` | archivo `QuadrantsData.gs` (cuadrantes) |

> **IMPORTANTE:** si modificas `Code.gs`, revisa también `Firebase.gs`.
> Las funciones de RTDB (`rtdbGet`, `rtdbGetAll`, `rtdbSetAll`) viven en
> `Firebase.gs`. Si en el editor el `Firebase.gs` queda viejo, fallan con
> `ReferenceError: rtdbGetAll is not defined`. El calendario mensual ya tiene
> un respaldo local (`_rtdbGetAllFallback` en `Code.gs`), pero igual debes
> actualizar `Firebase.gs` para el resto de funciones RTDB. Si el despliegue
> es versionado, crea una NUEVA VERSIÓN después de pegar los archivos.

## 2. Archivos del frontend
El proyecto se compila en un solo archivo HTML para compatibilidad con GAS.

Copia todo el contenido del siguiente archivo generado:

- **Local:** `Reporte_servicio/dist/index.html`
- **GAS:** Crea un archivo llamado `index.html` y pega el código.

Para generar `dist/` con el backend y el frontend listos para copiar:

```
npm run build:gas
```

Esto deja en `dist/`: `Code.gs`, `Firebase.gs`, `QuadrantsData.gs`, `index.html`,
`JavaScript.html`, `ReportJavaScript.html`, `styles.html` e `index.css`.

## 3. Configuración inicial
Si es la primera vez que ejecutas el script:
1. En el editor de GAS, selecciona la función `initialSetup` y ejecútala.

## 4. Configuración externa
Antes de publicar, revisa las constantes al inicio de `Code.gs`:

- `APP_CONFIG.SHEETS`: nombres de hojas usadas por la aplicación.
- `APP_CONFIG.EXTERNAL_PERSONNEL_SPREADSHEET_ID`: ID de la hoja externa de personal.

## 5. Notas importantes
- Los campos **Indicativo** y **Estado** sugieren valores basados en la hoja `DATA`.
- Si esas columnas están vacías, no habrá sugerencias pero se podrá escribir libremente.
- Los datos de personal dependen de la hoja externa configurada en `Code.gs`.

## 6. Cuota de UrlFetch (premium) y RTDB_SECRET
El error `premium urlfetch` aparece cuando se agota la cuota diaria de llamadas
autenticadas (compartida por toda la cuenta de Google, no por script).

1. En **Configuración del proyecto → Propiedades del script** agrega
   `RTDB_SECRET` con el secreto de Realtime Database
   (Firebase Console → Realtime Database → Secrets).
2. Verifica con la función `diagnosticoRtdb` (Ejecutar desde el editor): devuelve
   `modoEfectivo: "secret (?auth=)"` si el secreto está en uso, o
   `modoEfectivo: "oauth (Bearer)"` si no se encontró la propiedad (o el secreto
   fue rechazado con HTTP 401/403). También lista `origenSecret`
   (`script` / `usuario` / `documento` / `ninguno`) y las claves de las tres
   tipos de propiedades, para saber dónde debiste haberlo puesto.
3. Si `origenSecret` sale `ninguno`, el secreto NO está en ninguna propiedad de
   ese proyecto: ponlo en **Propiedades del script** con la clave exacta
   `RTDB_SECRET`, o ejecuta `configurarRtdbSecret("<secret>")` / `migrarRtdbSecret()`
   desde el editor (esta última copia de usuario/documento a script).
4. Si `secretRechazado: true` (HTTP 401/403), el secret existe pero no sirve para
   esa base de datos: revisa que sea el secret correcto de la RTDB
   (Firebase Console → Realtime Database → Secrets) y/o que sea para la misma DB.
   Luego ejecuta `resetRtdbQuotaFlag()` y `migrarRtdbSecret()`.
5. Si la cuota ya se agotó, el contador se reinicia cerca de medianoche hora del
   Pacífico (≈ 02:00–03:00 en Lima). Hasta entonces la app usa el respaldo en
   hojas y un cortacircuitos de 5 minutos para no reintentar RTDB en cada
   operación. `resetRtdbQuotaFlag()` borra esa marca manualmente.
6. Mientras la cuota esté agotada, los guardados se escriben **solo en la hoja**
   (`source: "sheets_fallback"`). Esos cambios no llegan a Firebase por sí solos:
   hay que revisarlos/sincronizarlos cuando vuelva la cuota.
7. Cuando vuelva la cuota, sincronizar los guardados que quedaron en la hoja:
   `resyncSheetsToRtdb(dateStr, shift)` (desde el editor, o vía doPost con
   `{ action: "resyncSheetsToRtdb", apiKey, dateStr, shift }`).
   Esto relee la hoja y reescribe en RTDB (un solo PATCH multi-path).
